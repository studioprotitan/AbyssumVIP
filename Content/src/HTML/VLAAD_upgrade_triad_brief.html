Correct Build Sequence

The three upgrades are dependent in sequence — the Contract defines the Mission, the Mission defines the Stages, the Stages update the Units. Build in this order to avoid rework:

Step 01
Unit Cards
Immediate visual payoff. Ties directly into SSoT. Sets up the entity model for everything downstream.
Step 02
Mission Spine
Adds structure and loop clarity. Spine reads from state — so Unit Card state already exists when wired.
Step 03
Contract Gen
Final injection: makes the cockpit alive. Contracts write to both Spine and Unit Cards via event bus.

Doctrine — Locked

Core Principles (Non-Negotiable)

No page loads. No UI transitions. Only: State Mutation → View Reactivity → World Consequences.

The Freight Car is the root view — immutable shell. Everything routes through it. The active viewport inside is the only thing that mutates.

Failure does not stop the system — it reshapes the world. Instability increments. Threat rises. The loop continues, just harder. This is the persistence-without-failure philosophy.

Drowning = true loss. Submerged + non-ejected = drowned flag = no recovery. No UI save-scumming.

"The View is constant. The State mutates. The World persists consequences." — Phase 3C Doctrine, locked.
